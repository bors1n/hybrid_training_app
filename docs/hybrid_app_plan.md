План реализации: приложение для гибридных тренировок (v3)

Название: HybridLog (медиа — Hybrid Training Russia). Дневник тренировок, в котором силовые, кардио и функциональные комплексы живут в одном месте, а прогресс виден по каждому направлению и в целом.

Версия 2 переписана по результатам интервью 27.10.2026. Версия 3 (27.10.2026): добавлены RPE и аккаунты с синхронизацией, экраны сведены к пяти вкладкам и входу по макетам на холсте «Экраны SPLAV» (https://claude.ai/artifact/2by4SC7AuvzFAQB8FMPKFT). Опорные документы проекта: инструкция «Что такое гибридные тренировки», hybrid_plan_basic.md, workouts_history.md.

3. Модель данных

Единицы хранения: вес — кг, дистанция — метры, время — секунды, темп — с/км, скорость — км/ч. Форматирование только на экране.

3.1. Упражнение Exercise
id, name, aliases[]                // «Тяга горизонтальная», «Тяга горизонтальная (seated row)»
kind: strength | bodyweight | cardio | core | mobility
equipment: barbell | dumbbell | kettlebell | machine | cable | smith | bodyweight | band | erg | none
muscles: { primary[], secondary[] }
perSide: boolean                   // выпады, тяга одной рукой
metrics: weight_reps | reps | time | distance_time
media?: { image, source, license }  // из каталога (раздел 4)
note?: string                      // постоянная заметка: настройка тренажёра
isCustom: boolean
3.2. Тренировка Session
id, userId, date, title, durationMin?, rpe? (1–10, вся тренировка), notes?
updatedAt, deletedAt?               // для синхронизации
type: strength | cardio | conditioning | mobility | mixed   // для статистики баланса
templateId?, queueSlot?             // если начата из шаблона или очереди
blocks: Block[]
3.3. Блоки

strength — упражнение или суперсет:

items: [{ exerciseId, sets: [{ weightKg?, reps?, durationSec?, perSide?, rpe?, done, load: 'normal' | 'added' | 'assisted' }], note? }]
superset: boolean

added — отягощение (+10 кг на поясе), assisted — противовес в гравитроне.

cardio:

modality: run | treadmill | bike | indoor_bike | skierg | row | stairs | walk | other
distanceM?, durationSec?, paceSecPerKm? (вычисляется), recordedPace?, avgHr?, floors?, inclinePct?, rpe?
role: main | warmup | finisher      // разминка 10 мин на дорожке не смешивается с пробежкой

conditioning:

complexId?: '#005', name?, format: AMRAP | EMOM | FOR_TIME | TABATA | INTERVALS | LADDER | ROUNDS | OTHER
timeCapMin?, description?
result: { rounds?, extraReps?, totalReps?, timeSec?, finished?: boolean }, rpe?, notes?

mobility — список упражнений с подходами или временем, общие минуты.

3.4. Шаблоны и очередь
Template { id, title, blocks (те же блоки, но с плановыми значениями: подходы, диапазон повторов, вес-ориентир) }
Queue    { id, title, templateIds[], position }      // Т1 → Т2 → Т3; несколько очередей возможно
Complex  { id: '#001', title, format, timeCapMin, description, tags[] }
ComplexQueue { order: ['#001', '#002', ...], position }

У каждой записи (шаблон, очередь, своё упражнение) есть userId, updatedAt, deletedAt?.

RPE хранится целым 1–10, пустое значение допустимо. В прогрессе показывается средний RPE по упражнению и по тренировкам; на расчёт 1ПМ он не влияет.

Очередь сдвигается, только когда завершена тренировка из этой очереди. Свободные тренировки и пробежки её не трогают.

5. Импорт истории: шаблон CSV

Файл import_template.csv лежит рядом. Одна строка — один подход, одна кардио-запись, один результат комплекса или одна строка мобильности. Строки одной тренировки объединяются по date + session.

Колонка	Обязательна	Пример	Пояснение
date	да	20.10.2026	ДД.ММ.ГГГГ
session	да	Тренировка 1	Название тренировки; одна дата + название = одна тренировка
session_type	нет	strength	strength / cardio / conditioning / mobility / mixed; если пусто, определяется по строкам
duration_min	нет	66	Длительность тренировки, пишется в любой её строке
kind	да	set	set / cardio / complex / mobility / note
order	да	1	Порядок упражнения в тренировке
exercise	для set, cardio, mobility	Присед со штангой	Сопоставляется со справочником по псевдонимам
superset	нет	A	Одинаковая буква = суперсет
set_no	для set	1	Номер подхода
weight_kg	нет	85	Вес; для assisted — противовес
load	нет	added	normal (по умолчанию) / added / assisted
reps	нет	8	Повторы
per_side	нет	1	1 = повторы на каждую ногу или руку
duration	нет	1:30	мм:сс или ч:мм:сс — для планки, кардио, комплекса на время
distance_km	для бега и вело	3.09	Точка или запятая
modality	для cardio	run	run / treadmill / bike / indoor_bike / skierg / row / stairs / walk / other
role	нет	warmup	main (по умолчанию) / warmup / finisher
pace	нет	7:46	Темп с часов; если пусто — вычисляется
avg_hr	нет	142	Средний пульс
floors	нет	80	Для лестницы
complex_id	нет	#005	Ссылка на библиотеку
complex_format	для complex	AMRAP	AMRAP / EMOM / FOR_TIME / TABATA / INTERVALS / LADDER / ROUNDS / OTHER
time_cap_min	нет	15	Длительность или лимит
rounds	нет	9	Полные раунды
extra_reps	нет	7	Повторы сверх полных раундов
total_reps	нет	184	Если считается суммой
notes	нет	угол 4	Заметка к строке
rpe	нет	7	RPE 1–10 подхода, кардио-записи или комплекса
session_rpe	нет	8	RPE всей тренировки, пишется в любой её строке

Проверки при импорте: дата в правильном формате и не в будущем; дата не нарушает порядок соседних тренировок (предупреждение, не ошибка); упражнение найдено в справочнике или будет создано новое; у подхода есть повторы или время; у кардио есть дистанция или время; RPE — целое от 1 до 10. Перед сохранением — экран со сводкой и списком предупреждений. Повторный импорт того же файла не создаёт дубликаты (ключ: дата + название тренировки).

6. Экраны MVP

Макеты: холст «Экраны SPLAV». Нижняя панель — четыре вкладки: Сегодня, План, Прогресс, Каталог. Тренировка открывается кнопкой, профиль — кружком с буквой справа сверху.

Сегодня. Тёмная карточка следующей тренировки в очереди (состав и прошлые веса, кнопки «Начать» и «Короткая»), следующий комплекс, последняя пробежка, «Свободная тренировка», последние тренировки.
Тренировка (полноэкранная, открывается поверх вкладок). Блоки сила, кардио, комплекс, мобильность; «Добавить блок». У упражнения — прошлый результат и заметка; строка подхода: №, прошлый, кг, повторы, RPE, отметка. Новый подход копирует прошлый. Суперсет — общая карточка с кругами. Кардио — дистанция, время, темп (авто), пульс, RPE. Комплекс — экран результата: раунды + повторы или время, RPE. Внизу итог: время, тоннаж, км, RPE тренировки, заметка. Сохраняется при каждом изменении, можно внести задним числом.
Прогресс. Вкладки Сила, Кардио, Комплексы, Баланс; ниже — история с поиском, фильтром по типу, редактированием и удалением (отдельного экрана истории нет).
Сила: по упражнению — график расчётного 1ПМ (Эпли) и рабочего веса, рекорд, последний подход, средний RPE, тоннаж по неделям.
Кардио: по виду (бег, вело, остальное) — км и минуты по неделям, тренд темпа, лучшие результаты.
Комплексы: история результатов по каждому комплексу.
Баланс: минуты силы, кардио, комплексов и мобильности по неделям, теплокарта активности, недели подряд.
План. Очередь Т1 → Т2 → Т3 (в стиле беговых дорожек), шаблоны и их редактор, новый цикл, библиотека комплексов #001–#024 с отметками «рекорд», «следующий», «не делал».
Каталог. Поиск, фильтры (тип, мышцы, оборудование, свои), картинки RepDB, свои упражнения, история по упражнению.
Вход. Почта с кодом, Apple, Яндекс ID. После входа история подтягивается с сервера.
Профиль (шторка из кружка): аккаунт, импорт CSV и Excel, экспорт CSV и JSON, единицы, «О приложении» с указанием RepDB, выход.
7. Стек
Слой	Выбор
Клиент	React + TypeScript + Vite, PWA (vite-plugin-pwa), React Router
Состояние	Zustand
Хранение на устройстве	IndexedDB через Dexie — локальная копия и очередь изменений для работы без сети
Сервер	Node + Fastify + PostgreSQL (или SQLite на старте), REST API, Zod-схемы общие с клиентом
Аккаунты	Вход по коду на почту (magic code), Sign in with Apple, Яндекс ID; сессия — httpOnly-cookie или токен с обновлением
Синхронизация	Last-write-wins по updatedAt на уровне записи, мягкое удаление deletedAt, pull по since + push очереди изменений
Схемы	Zod
CSV / Excel	Papa Parse, SheetJS (xlsx)
Графики	Recharts
Тесты	Vitest
Позже	Capacitor для App Store

Риск iPhone снят сервером: если Safari очистит локальные данные, они вернутся с сервера после входа. Не отправленные изменения хранятся в очереди и уходят при первой связи; на экране — значок «не синхронизировано».
