# Принятые решения

Новые записи — сверху в рамках этапа. Формат: решение, причина.

## Доработки по ревью этапов 0–5 (29.10.2026)

Источник — `полный_тест_5_этапов.txt`. Порядок работ: Р1 «Сегодня» → Р2 «Прогресс» → Р3 «Программы» → Р4 библиотека комплексов и «Каталог» → Р5 аватар. План — в `docs/` не копировался, лежит у автора.

**Р1. «Сегодня»**
- **«Короткая» убрана целиком** (кнопка, `inShort` в схеме шаблона, редактор, сид, `hasShortVersion`). Пользователь не пользуется ей. Старые записи шаблонов с `inShort` проходят проверку: Zod отбрасывает лишнее поле, а при следующем сохранении оно исчезает. Записи DECISIONS.md про короткие версии (этапы 2 и 4) устарели.
- **Компоновка:** карточка очереди с кнопкой «Начать» по центру (по ширине содержимого) → «Свободная тренировка» → «Последние».
- **«Последние»:** карточка последнего **выполненного** комплекса (любой блок с результатом, в том числе свой, без номера из библиотеки), карточка последнего кардио любого вида (только `role: main`; бег — темп, остальное — скорость), затем список тренировок. Карточки считают чистые `lastComplexAttempt` (`complexResults.ts`) и `lastCardioEntry` (`lastCardio.ts`); прежние мини-карточки «следующий комплекс» и «последняя пробежка» и `lastRun.ts` удалены. Очередь комплексов по-прежнему видна на экране «План».

**Р2. «Прогресс»**
- **Вкладки:** Баланс → Сила → Выносливость (бывшее «Кардио») → Комплексы; открывается «Баланс». «Баланс недели» (`WeekBalanceCard`) удалён, «Регулярность» перенесена только на «Баланс»; история остаётся под всеми вкладками.
- **Баланс сила — выносливость** (`strengthEnduranceBalance`): считается число тренировок, не минут, за последние **4 недели** (текущая и три предыдущие; ни «за всё время», ни переключателя периода). Сила — есть выполненный силовой подход; выносливость — кардио с дистанцией или временем либо комплекс с результатом. Смешанная тренировка идёт в обе стороны, мобильность не учитывается. Показаны только числа, без оценки «хорошо/плохо».
- **Огонёк** у «Рекорда серии» — значок `FlameIcon` цвета `--conditioning`, показывается, когда рекорд больше 0. Это оранжевый элемент рядом с оранжевой серией «Комплексы» в графиках минут: правило «один оранжевый на экране» тут нарушено осознанно, по просьбе.
- **«Минуты по неделям»:** подсказка «силовые — остаток длительности» убрана. Сами минуты считаются как раньше (силовые — остаток длительности тренировки).
- **Сила:** сверху общий блок за 4 недели (тренировок, подходов, тоннаж в тоннах) и «Тоннаж по неделям» по всем упражнениям за 12 недель (`strengthOverview`, `overallWeeklyTonnage`; только обычный вес, как и тоннаж упражнения). Ниже — анализ упражнения без изменений.
- **Выносливость:** чипы «Все» (по умолчанию) · Бег · Вело · Другое. Для «Все» плитки — дистанция, время, число записей; для группы — прежние рекорды. «Километры по неделям» — линия с градиентной заливкой (`AreaTrendChart`, как в Strava), «Минуты по неделям» — столбцы; недели без кардио заполнены нулями (`weeklyCardioFilled`). Темп у «Все» строится по бегу (подсказка « · бег»): темп и скорость у видов несравнимы. Таблица «Последние записи» убрана — внизу история.
- **Комплексы:** плитки «комплексов / повторов / раундов» и лента карточек «комплекс + выполнение», новые сверху (`complexFeed`, `complexTotals`); повторы одного комплекса — отдельные карточки, нейтральная метка «рекорд» у лучшей из нескольких попыток. «Повторы» — то, что записал человек: `totalReps`, а без него `extraReps`; из раундов повторы не выводятся (состав раунда неизвестен). Аккордеон по библиотеке и строка «Ещё N не делали» убраны; динамика одного комплекса — в листе комплекса на экране программы.

**Р3. «Программы» вместо «Плана»**
- **Модель:** новая синхронизируемая коллекция `programs` (`title`, `description?`, `queueId`, `complexQueueId`). Программа ссылается на существующие `queues` и `complexQueue`, а не встраивает их: `queueId` в уже записанных тренировках остаётся верным, миграции данных нет. Активная программа — поле `activeProgramId` в записи `settings` (`id = 'settings'`); нет поля или программа удалена → базовая `seed:program:basic`, а если и её нет — первая по id (`activeProgram`). Dexie v4, `SEED_VERSION = 2`.
- **«Базовая программа»** (`seed:program:basic`) — прежние Т1–Т3 (`seed:queue:cycle`) и очередь комплексов `seed:complexQueue:main`. Комплекс #004 в этой очереди не стоит (так было и раньше), поэтому в программе его плитки нет: добавляется кнопкой «+ Комплекс». Раньше экран «План» показывал все 24 комплекса библиотеки, теперь программа показывает только свои.
- **Пустые очереди:** `templateIds` и `order` теперь могут быть пустыми (новая программа начинается пустой), поэтому правило «единственный шаблон очереди удалить нельзя» снято; `queueState`/`complexQueueState` на пустой очереди возвращают `null`.
- **Экраны:** вкладка «Программы» (`/programs`, заголовок «Программы тренировок») — карточки программ с меткой «Активная» и «N тренировок · M комплексов», «+ Создать программу»; `/programs/:id` — бывший «План» для одной программы (очередь, «+ Шаблон», шаблоны вне очереди, комплексы программы с «+ Комплекс», «Тренировка вне очереди», «О программе»: название, описание, «Сделать активной», удаление). `/plan` перенаправляет на `/programs`. «Сегодня» оставляет подпись «Свободная тренировка»: переименование только на экране программы, как в ревью.
- **«Шаблоны вне очереди»** — шаблоны, которых нет ни в одной программе (раньше «нет в единственной очереди»). Добавить любой шаблон в очередь программы можно в «Изменить».
- **Запуск:** `startTemplateWorkout(templateId, { queueId })` — очередь называется явно (с экрана программы и из активной программы на «Сегодня»); без неё берётся первая очередь с этим шаблоном. Очередь комплексов — у программы той очереди (раньше брался первый документ).
- **«Новый цикл» убрана** (по решению пользователя): кнопка и `queueNewCycle`. «Начать с…» в редакторе очереди остаётся, «ЦИКЛ N» считается как раньше.
- **Свои комплексы:** «+ Комплекс» → «Из библиотеки» (поиск, без уже добавленных) или «Создать свой» (название, формат, лимит, состав; id `own:<uuid>`, сразу попадает в программу). «Убрать из программы» убирает комплекс только из очереди этой программы; запись комплекса и его результаты остаются.
- **Удаление программы** мягкое и убирает её очереди (`queues`, `complexQueue`); шаблоны, комплексы и записанные тренировки остаются. Удаление последней программы допустимо: «Сегодня» без неё карточки очереди не показывает.
- Комплексы sportkuznica.com и каталожные цвета — Р4; аватар — Р5.

## Сайт Hybrid Training Russia: С2 (статьи)

- **Коллекция** `articles`: Markdown в `site/src/content/articles/`, имя файла = адрес статьи. Поля: `title`, `rubric` (programs, running, strength, complexes, recovery), `date`, `lead`, необязательные `cover` (путь вида `/covers/…`), `readingTime` и `draft`. Если `readingTime` не указан, считается по тексту (180 слов в минуту, не меньше минуты, разметка не считается). Черновики собираются только в dev.
- **Адреса.** Список — `/articles/`, статья — `/articles/<файл>/`, рубрика — `/rubrics/<ключ>/`. Рубрики отдельными страницами, а не фильтром в адресе: сайт статический, без JavaScript. Рубрики без статей показывают «пока нет статей», а не пропадают из меню.
- **Страница статьи.** Макета нет, поэтому сделана по дизайн-системе: колонка 680 px, крупный текст 19 px с межстрочным 1,65, голубая рубрика-наклейка, заголовок Unbounded 800, вводный абзац, дата и время чтения, блок «Ещё в рубрике», призыв перейти к SPLAV. Обложка выводится, только если указана. Если нарисуете макет страницы, подгоним.
- **Первая статья** — «Что такое гибридные тренировки», целиком из `docs/Что такое гибридные тренировки.md` (текст автора, структурирован заголовками). Других статей я не сочинял: тексты и факты — только ваши. Слово «capacity» из исходного текста оставлено как есть.
- **Главная:** из заглушек макета остались только фото-подписи в первом экране; «Свежие статьи» — три последних из коллекции, пока она состоит из одной статьи, карточка одна.
- **Тесты.** Чистые функции — `site/src/lib/articles.test.ts` (рубрики, время чтения, даты, порядок); компоненты — через Astro Container API. Страницы с коллекцией проверяются сборкой (`npm run build`).

## Сверка с макетами (после этапа 5)

Макеты «Экраны SPLAV» сверены с реализацией по всем семи экранам. Приведено к макету:

- **Прогресс** (`Progress.dc.html`): активная вкладка тёмная; главная карточка силы — выбор упражнения с «N недель», крупный расчётный 1ПМ с изменением («+12 кг» — разница между первой и последней тренировкой, просто число), график с оранжевой последней точкой, плитки «Рекорд» (подход с наибольшим расчётным 1ПМ), «Последний», «Ср. RPE»; под вкладками всегда «Баланс недели» (полоса минут и легенда) и «Регулярность» (полгода, 26 недель, четыре оттенка как на макете); история с цветными точками по видам блоков и RPE. Остальное из ТЗ (тоннаж, лучший подход по повторам, кардио, комплексы, недельные графики) осталось под главной карточкой и на своих вкладках. Теплокарта и недельный баланс убраны с вкладки «Баланс», чтобы не дублироваться.
- **Тренировка** (`Workout.dc.html`): RPE всей тренировки — ползунок 1–10 с подписями «легко / тяжело / предел» и «Сбросить» (RPE необязателен; пока не выбран, ползунок пустой); в шапке «Цикл N · …» для идущей тренировки из очереди; суперсет — компактные строки (название, прошлый результат, подход текущего круга) и полоска кругов, ввод раскрывается нажатием на упражнение.
- **Комплекс** (`WorkoutComplex.dc.html`): в тренировке — тёмная карточка-сводка с кнопкой «Открыть», ввод результата — на отдельном экране `/workout/:id/complex/:blockId` (крупное название, состав по строкам, панель результата с «−»/«+» раундов, «Записать результат»). Формат и лимит — в раскрывающемся блоке «Параметры комплекса». Перед открытием экрана несохранённые правки тренировки дописываются в базу (иначе экран комплекса мог бы не найти только что добавленный блок).
- **Каталог** (`Library.dc.html`): блок «Часто делаешь» (пять упражнений по числу тренировок) с подписью «1ПМ N кг» или лучшим подходом; **вход** — подсказка про загрузку CSV.

Осознанные отличия от макетов (MVP): нет таймера AMRAP, паузы, бейджа «+2,5 кг» и «Отдыха 2:00» (принцип «приложение не решает за человека» и ТЗ); кнопки Apple и Яндекс ID на входе; в итоге тренировки кнопка «Завершить тренировку» вместо «Сохранить» (завершение двигает очередь); заголовок «План» показывает только «ЦИКЛ N» без «неделя 3 из 4» (в данных нет понятия недели цикла); каталог остаётся с тремя рядами фильтров-чипов с горизонтальной прокруткой (решение пользователя).

## Этап 5. Прогресс

- **Что считается.** Только выполненные подходы (`done`) неудалённых тренировок; завершённость тренировки не требуется (импортированная история `finishedAt` не имеет). Расчёты — чистые функции в `domain/` (`strengthMetrics`, `cardioMetrics`, `balanceMetrics`, `complexMetrics`, `weeks`), экран только показывает.
- **Серии по типу нагрузки.** Для упражнения обычный вес, отягощение (`added`) и противовес (`assisted`) — три отдельных раздела со своими графиками. Расчётный 1ПМ (Эпли, подходы 1–12 повторов) и тоннаж — только у обычного веса: у отягощения и противовеса вес тела неизвестен, их 1ПМ был бы выдумкой. У противовеса «лучше» — меньше (ось графика перевёрнута, плитка «минимум противовеса»).
- **Рабочий вес** — наибольший вес выполненного подхода тренировки; «1ПМ расчётный» на плитке — лучший за всё время. Лучший подход по повторам — наибольший вес на каждое число повторов с датой. Средний RPE — по подходам, где RPE указан.
- **Кардио.** Группы: Бег = улица + дорожка, Вело = велосипед + велотренажёр, остальное — Другое. Км и минуты по неделям включают разминки и финиши; темп — только основная часть (`role: main`). Показывается темп с часов (`recordedPace`), иначе сохранённый расчётный. Лучший темп и скорость — только на дистанции от 1 км (рывок 400 м темпом не считается). Для вело и «другого» вместо темпа показывается скорость, км/ч.
- **Минуты силы** (правило из плана): длительность тренировки (введённая вручную, иначе по часам до 12 часов) минус известные минуты кардио, комплекса (время результата, иначе лимит) и мобильности. Нет длительности — силовые минуты неизвестны и считаются нулём, а не угадываются; остаток не уходит в минус; нет выполненных силовых подходов — ноль.
- **Недели** начинаются с понедельника; даты — строки ГГГГ-ММ-ДД, арифметика через UTC-день, без часовых поясов. «Недель подряд» считается назад от текущей недели; если на текущей ещё не было тренировок, серия не обрывается (неделя не закончилась), считается от прошлой. Рекорд серии показывается рядом.
- **Теплокарта** — своё SVG, 53 недели, один цвет силы с тремя уровнями прозрачности (1, 2, 3+ тренировок в день); будущие дни не рисуются.
- **Комплексы.** Список — только с попытками (остальные одной строкой «ещё N не делали»); раскрытие показывает график и историю с рекордом. График: «на время» — секунды (меньше лучше), AMRAP — раунды (добор повторов на графике не показывается: у разных комплексов у него нет общей меры, в списке он есть).
- **Цвета баланса.** Столбцы с накоплением используют цвета типов (сила, кардио, комплекс, мобильность), смешанная — нейтральный. Оранжевый комплекса в легенде графика — это цвет типа, не акцент экрана.
- **Новая зависимость: `recharts` 3.10.1 (+ `react-is`).** Нужна для графиков (по плану). Грузится отдельным куском 389 КБ (gzip 111 КБ) только при открытии вкладки с графиком; офлайн он доступен — кусок в precache service worker.
- **Не делалось:** сравнение периодов, цели и оценки («приложение не решает за человека»), графики по комплексам вне библиотеки.

## Этап 4. Шаблоны и очередь

- **Очередь вычисляется из истории** (`domain/queue.ts`): следующий шаблон — слот последней завершённой тренировки этой очереди + 1; новый цикл начинается, когда слот не больше предыдущего (можно начать шаблон не по порядку). Свободные тренировки, пробежки и шаблоны вне очереди её не трогают по построению. «Новый цикл» и «Начать с…» — `override { position, setAt }`, действует, пока после `setAt` не завершена тренировка очереди.
- **Очередь комплексов** сдвигается, только когда завершённая тренировка содержит блок комплекса, равный ожидаемому. «Сделать следующим» ставит комплекс первым в порядке очереди (комплекс вне очереди, например #004, вставляется).
- **Предзаполнение — копия, а не рекомендация.** Подходы берутся из последней выполненной тренировки (только done-подходы; вес — если тип нагрузки совпал), иначе вес — ориентир из шаблона. Подходы не отмечаются выполненными; при завершении неотмеченные предлагается отметить или убрать. Никаких автоматических прибавок.
- **Пустые заготовки** шаблона (разминка, финиш, комплекс без результата, мобильность без отметок), в которые ничего не внесли, при завершении не сохраняются (`dropEmptyBlocks`); если не осталось блоков — тренировка считается пустой.
- ~~**Короткая версия** — блоки с `inShort`; у Т3 её нет, кнопка скрыта.~~ Отменено 29.10.2026, см. «Доработки по ревью».
- **Удаление шаблона:** из очередей он убирается; сделанные тренировки остаются; единственный шаблон очереди удалить нельзя.
- **Редактор шаблона** сохраняется сам (как журнал, `useRecordDraft`, 300 мс); диапазоны повторов и веса нормализуются, подходов не меньше 1; время кардио и мобильности — в минутах на экране, секунды в данных.
- **Новых зависимостей нет.**

## Этап 3. Импорт и экспорт

- **Три шага.** Разбор файла в таблицу (`csvText.ts`) → план (`buildImport`, чистая функция) → экран проверки → запись (`applyImport`). Пока человек не нажал «Импортировать», в базе ничего не меняется. Экран не даёт выбрать файл, пока не загрузились библиотека комплексов, сохранённые сопоставления и журнал (иначе план мог бы собраться без них).
- **Файлы.** CSV: UTF-8 с BOM и без, разделитель `,` `;` Tab или `|` определяется сам, переводы строк CRLF, LF и CR, кавычки по стандарту. Если байты не читаются как UTF-8, файл читается как Windows-1251 (так Excel на русской Windows сохраняет «CSV»). Excel — первый лист, SheetJS 0.20.3 с cdn.sheetjs.com (npm-версия устарела), подгружается отдельным куском (361 КБ) только при выборе .xlsx/.xls. Значения берутся как их видит человек: дата по формату ячейки превращается в ДД.ММ.ГГГГ независимо от региона, «10:00» остаётся временем 10:00, а не числом-долей суток. Пустые строки пропускаются, но номера остальных сохраняются: ошибки указывают на строку файла (заголовок — строка 1).
- **Ошибка или предупреждение.** Ошибка — строка не импортируется: неверная или будущая дата, нет названия тренировки, неизвестный `kind`, нет `order`, у подхода нет повторов и времени, у кардио нет дистанции и времени, неизвестные вид кардио, роль, формат комплекса, нагрузка, `per_side`, число или время не в формате, **RPE не целое 1–10** (молча отбрасывать RPE нельзя — потерялось бы значение, поэтому строка не принимается). Предупреждение — строка импортируется: даты идут не по порядку (тренировка раньше предыдущей в файле; в шаблоне так нарочно, их 5), темп с часов отличается от расчётного больше чем на 5%, неизвестный `session_type` (тип определён по содержимому), несколько упражнений в блоке без буквы суперсета, разная длительность или RPE тренировки в строках, комплекса нет в непустой библиотеке. Все ошибки строки показываются сразу, а не по одной.
- **Блоки.** Силовые строки с одним `order` — один блок, мобильность тоже; каждая строка кардио и комплекса — отдельный блок; блоки разных видов с одним `order` не склеиваются. Больше одного упражнения в блоке — суперсет независимо от букв (без букв — предупреждение). Подходы идут по `set_no`, без номеров — по порядку строк. Строки `note` склеиваются в заметку тренировки. Тип тренировки: `session_type` из файла, иначе по блокам.
- **Идентификаторы детерминированные.** Тренировка: `imp-<дата>-<хэш названия>` (или id уже существующей тренировки с той же датой и названием); блок: `<id тренировки>:<номер блока>`; своё упражнение: `imp-ex-<хэш названия>`. Поэтому повторный импорт на любом устройстве даёт те же записи, а два устройства, импортировавшие один файл независимо, сходятся без дублей (проверено сквозным тестом через сервер).
- **Повторный импорт.** Совпало до последнего поля — «без изменений», ничего не пишется (даже в очередь отправки). Отличается от журнала — «заменить», только по галочке (по умолчанию выключена); без неё существующая тренировка остаётся. Удалённая ранее тренировка при импорте возвращается. Ключ сопоставления — дата + нормализованное название (регистр, пробелы, ё/е не важны).
- **Время тренировки.** Импортированные тренировки завершены (`finishedAt` — полдень даты), `startedAt` нет, длительность — из `duration_min`.
- **Комплексы.** Если в файле не указаны формат, лимит или название, они берутся из библиотеки (вместе с описанием состава); значения файла важнее.
- **Упражнения.** Название ищется в каталоге и своих (регистр, ё/е, скобки, псевдонимы, сохранённые сопоставления). Не нашлось — создаётся своё упражнение с выведенными свойствами (вес → «вес и повторы», только повторы → «свой вес», только время → «время», мобильность → «мобильность»). На экране проверки каждое такое название можно сопоставить с каталогом (выбор запоминается как `exerciseAliases`) или оставить «создать своё». Неоднозначное название — выбор из кандидатов, по умолчанию первый. Список «что решить» строится по разбору без выбора, поэтому строка не исчезает после выбора.
- **Экспорт CSV** — тот же формат: BOM (иначе Excel ломает кириллицу), разделитель «,», десятичная точка, дата ДД.ММ.ГГГГ, тренировки по возрастанию дат. Экспортируются только выполненные подходы; расчётный темп не пишется (при импорте считается заново), пишется темп с часов. Общие данные тренировки (тип, длительность, RPE) — в первой строке, заметка — строкой `note`. Что в шаблоне негде хранить, не молчит, а попадает в список предупреждений после экспорта: наклон дорожки, «не уложился», общее время блока мобильности, подход без повторов и времени (при импорте он будет отклонён), невыполненные подходы, упражнение, которого нет в каталоге. Инвариант «импорт ∘ экспорт = тождество» проверяется тестами на шаблоне и на базе.
- **Экспорт JSON** — все коллекции без удалённых записей, с версией формата и временем; каталог RepDB не входит. Файл отдаётся через системное меню «Поделиться» (на iPhone — сохранить в «Файлы»), если оно доступно, иначе обычным скачиванием.
- **Шаблон** скачивается из приложения (`/import_template.csv`, попадает в офлайн-кэш). Это копия `docs/import_template.csv`; совпадение проверяет тест.
- **Не сделано:** экспорт в Excel (достаточно CSV: Excel его открывает), отдельный экран управления сохранёнными сопоставлениями, чтение Windows-1251 проверено на уровне декодера, а не реальным файлом из Excel.

## Этап 2. Журнал

- **Жизненный цикл тренировки.** «Свободная тренировка» сразу создаёт запись на сегодня (без `finishedAt`). Незавершённая тренировка видна на «Сегодня» как «Продолжить» — так закрытие приложения посреди занятия ничего не теряет. «Завершить» ставит `finishedAt`; законченную можно открыть из истории и «Продолжить тренировку» (снимает `finishedAt`). Пустую тренировку без блоков при завершении предлагается удалить (мягко, как любую запись).
- **Сохранение.** `useSessionDraft` держит копию в состоянии; каждая правка видна сразу и уходит в `saveRecord` через 300 мс. Запись принудительно сбрасывается при уходе с экрана, при скрытии вкладки (`visibilitychange`) и `pagehide`. Поле ввода отдаёт значение при уходе из него или Enter; некорректный ввод (RPE 11, текст вместо числа, дробные повторы) откатывается, пустое поле очищает значение. Если сохранить нельзя (схема), экран показывает ошибку, а правка остаётся в памяти.
- **Подход «выполнен».** Ввод значения (вес, повторы, время, RPE) сам отмечает подход выполненным; явная отметка важнее. Причина: при внесении тренировки задним числом не нужно жать галочку у каждого подхода. «+ Подход (копия)» копирует вес, повторы, время и нагрузку предыдущего подхода, но не отметку и не RPE, поэтому копия, которую не трогали, остаётся невыполненной. При завершении приложение спрашивает про такие подходы: «Отметить выполненными» или «Убрать эти подходы». В итоги, тоннаж и прошлый результат идут только выполненные.
- **Новое упражнение начинается с копии первого подхода прошлого результата** (не отмечена выполненной). Это копия того, что человек делал сам, а не рекомендация, поэтому принципу «приложение не решает за человека» не противоречит.
- **Прошлый результат** — последняя тренировка с этим упражнением не позже даты текущей (при внесении задним числом «прошлое» — то, что было до выбранной даты), без самой редактируемой. В одном дне порядок по времени начала.
- **Тоннаж** = сумма «вес × повторы» по выполненным подходам с обычным весом; подходы с отягощением и противовесом не входят (собственный вес неизвестен); при «на сторону» считаются обе стороны (15 кг × 12 на ногу = 360). Километры и время кардио включают разминки и финиши.
- **Тип тренировки** выводится из блоков при каждой правке (`deriveSessionType`): разминки, финиши и мобильность не считаются; один вид основной работы — он и тип, несколько — «смешанная»; без основной работы — мобильность, затем кардио. Вручную тип не задаётся.
- **Нагрузка** (обычный вес / отягощение / противовес) задаётся упражнению целиком и наследуется новыми подходами; выбор показывается для упражнений со своим весом и тренажёрных. Так «подтягивания +10 кг» и «в гравитроне 18,5 кг» различаются в данных, подписи колонки (`КГ`, `+КГ`, `−КГ`) и истории.
- **Время подхода** (планка, статика): кнопка «+ Время» включает колонку у любого упражнения; в одном упражнении можно смешивать подходы на время и на повторы (как в истории «2 мин статика, 1 — 15»).
- **Кардио.** Расчётный темп хранится всегда, когда есть дистанция и время; темп с часов — отдельное поле и показывается вместо расчётного. При расхождении больше 5% — предупреждение, как при импорте. В поле времени одно число понимается как минуты («20» = 20:00). Название блока следует за видом, пока его не меняли.
- **Комплексы без таймера** (макет с таймером нарисован, но таймеры в MVP не входят). Результат по формату: AMRAP и остальные — раунды (кнопки −/+) и повторы сверху; «на время» (на время, раунды на время, лесенка) — время и флажок «Не уложился»; EMOM, табата, интервалы, другое — ещё и «всего повторов». Рядом с блоком — прошлая попытка и рекорд. Сравнение (`resultScore`): AMRAP — больше раундов и повторов лучше; на время — быстрее лучше, незавершённый хуже любого завершённого; при равенстве рекорд за более ранней попыткой. Логика готова для этапа 5.
- **Блоки** перемещаются кнопками ↑↓ (перетаскивания нет), удаление блока и упражнения — в два нажатия (первое просит подтвердить, через 4 с сбрасывается). Суперсет — упражнения в общей карточке, «+ Круг» добавляет подход каждому. Дата выбирается встроенным полем даты, не позже сегодняшней.
- **История** живёт под вкладкой «Прогресс» (отдельного экрана истории нет): поиск по названию и заметке и по дате целиком (`20.10.2026` или `2026-10-20`), фильтр по типу, открытие для правки, удаление мягкое. Дата распознаётся до разбиения на слова: иначе «20», «10», «2026» совпадали бы с любой тренировкой (поймал тест).
- **Не сделано в этом этапе (по плану дальше):** шаблоны, «Начать» и «Короткая» (этап 4), графики и баланс (этап 5), импорт и экспорт (этап 3). Постоянная заметка упражнения показывается в карточке, но редактируется в каталоге; заметка к упражнению внутри одной тренировки (`setItemNote`) есть в логике, в интерфейсе её пока нет.

## Экран «Каталог» (после этапа 1)

- **В плане v3 экран «Каталог» не закреплён ни за одним этапом** (этап 1 — только данные, этап 2 — журнал). Сделан отдельно, после этапа 1, по макету `Library.dc.html`. «История по упражнению» и «1ПМ» в строках макета появятся с журналом и прогрессом: пока истории нет, показывать нечего.
- **Поиск**: все слова запроса должны найтись внутри *одного* названия или *одного* псевдонима. Раньше слова искались по всем псевдонимам вместе, и «кор комплекс» находил «Мобильность таза» (псевдонимы «Мобильность ТБС, Кор» и «…, комплекс»). Результаты упорядочены: точное название, начало названия, начало слова, остальное.
- **Фильтры**: тип (с точкой цвета типа), группа мышц по *основным* мышцам (грудь, спина, плечи, руки, ноги, ягодицы, кор), оборудование, «Свои». Список показывается порциями по 60 (всего 658 строк), картинки грузятся лениво.
- **Свои упражнения** — коллекция `exercises`, синхронизируются; название не должно совпадать с существующим (без учёта регистра и ё/е), иначе импорт не сможет выбрать упражнение. Режим ввода выводится из типа (`defaultMetrics`). Упражнения автора (`splav:*`) — часть каталога, их нельзя удалить; свои удаляются мягко, а тренировки, где они использованы, сохраняются.
- **Заметка** к любому упражнению — запись `exerciseNotes` с `id` = id упражнения; сохраняется при потере фокуса и при закрытии карточки, пустой текст удаляет заметку. Подпись «Exercise data by RepDB (repdb.co)» — в карточке каждого упражнения из RepDB.
- **Компонентные тесты**: добавлены `jsdom` и `@testing-library/react` (dev). Файл включает DOM строкой `// @vitest-environment jsdom` первой строкой; остальные тесты клиента идут в `node`.

## Этап 1. Модель и справочник

- **Схемы лежат в `shared/src/schemas/`** и общие для клиента и сервера. `RECORD_SCHEMAS` — по схеме на каждую синхронизируемую коллекцию; `checkRecord` проверяет форму записи и её согласованность с конвертом (`id`, `updatedAt`, `deletedAt`).
- **Сервер проверяет `data` и отклоняет невалидные записи по одной** (поле `rejected` в ответе push), а не всю пачку: одна плохая запись не должна блокировать синхронизацию. Неизвестные поля отбрасываются — новый клиент не ломает старый сервер. Клиент убирает отклонённые записи из очереди и пишет их в `meta.rejectedRecords` (последние 20) для диагностики; без этого очередь застряла бы навсегда.
- **`saveRecord` проверяет запись по схеме до сохранения** и бросает `ZodError`: на сервер не уходит то, что он всё равно отклонит. Значения по умолчанию (`done: false`, `load: 'normal'`, `role: 'main'`) сохраняются в записи.
- **`userId` в клиентских записях нет**: владелец известен серверу из сессии (проще и безопаснее, чем хранить его в данных).
- **Дополнения к модели из плана**: у тренировки `startedAt`/`finishedAt` (завершённая = есть `finishedAt`) и `queueId` вместе с `queueSlot` (очередей может быть несколько); у кардио `name` (для колонки `exercise` при экспорте); у блока шаблона `inShort`, у плана подходов — верх диапазона веса `weightKgMax` (14–16 кг); у блока шаблона-комплекса `fromQueue`; у очередей `override` вместо хранимой позиции.
- **Позиция очереди не хранится**, а вычисляется из завершённых тренировок (этап 4). Ручной выбор («Новый цикл») — `override { position, setAt }`: действует, пока после `setAt` не завершена тренировка этой очереди.
- **Каталог = RepDB + упражнения автора, статичный, в базе не хранится.** В базе (коллекция `exercises`) только упражнения, созданные пользователем. Заметки к упражнениям каталога — коллекция `exerciseNotes` (`id` = id упражнения), запомненные при импорте сопоставления — `exerciseAliases`. id: `repdb:<slug>` (каталог), `splav:<slug>` (упражнения автора), uuid (созданные пользователем).
- **Каталог RepDB собирается скриптом** `npm run seed:media` и не хранится в git: по лицензии нельзя распространять набор данных, в том числе производный. Скрипт проверяет, что в лицензии по-прежнему есть четыре условия, на которые рассчитан проект (бесплатно с атрибуцией, запрет распространения как набора данных, запрет генеративного ИИ), и падает, если они изменились. Картинки кэшируются service worker при первом просмотре (CacheFirst, до 1500 файлов), а не в precache: их больше тысячи.
- **Русские названия**: сначала проверенные вручную (`programExercises.ts`, только для упражнений программы и истории), затем перевод всех 650 (`catalog.ru.json`), затем английское. Английское и переведённое названия остаются псевдонимами. Тест следит, чтобы русские названия не повторялись: при совпадении импорт не смог бы выбрать упражнение (поймал «Выпады», «Ягодичный мост со штангой», «Отжимания на кольцах»). Латиницей намеренно оставлены dead bug, SkiErg, V-ups, push press, 90/90.
- **Сопоставление названий** (`domain/matching.ts`): регистр, ё/е, знаки, скобки (целиком, без скобок и только содержимое скобок). Одно название у двух упражнений — «неоднозначно», решает человек. Запомненные сопоставления важнее поиска. Спорные соответствия сознательно не угадываются: «Жим гантелей» без уточнения и «Наклоны с гирей» останутся «новыми» при импорте.
- **Seed** создаётся после первой успешной синхронизации (`ensureSeed`), с `updatedAt = 1` и детерминированными id (`seed:template:t1`, `seed:queue:cycle`, `#001`…`#024`, `seed:complexQueue:main`). Любая правка пользователя новее; два устройства, засеявшие независимо, сходятся без дублей; удалённая запись заново не создаётся. Версия набора хранится в `meta.seedVersion`.
- **Очередь комплексов — без #004**, как в программе («#001, #002, #003, #005, #006 … #024»): это короткий комплекс для разгрузочного цикла. Метки `короткий`, `интервальный` (#004, #009, #017, #021 — после них спринты не нужны) и `вес тела` взяты из текста программы; автоматических правил на них нет.
- **Т3 содержит «Спринты 6 × 40/40» как блок-комплекс (INTERVALS)**, а не как кардио с интервальной структурой: интервалы в кардио в MVP не входят. Разминки и финиши в шаблонах — кардио-блоки с ролями `warmup`/`finisher` и диапазоном времени (`durationSec`…`durationSecMax`).
- ~~**Короткие версии**~~ (отменены 29.10.2026): Т1 — пункты 1–3 и 7 (присед, жим, тяга, кор + разминка), Т2 — пункты 1–4; остальное помечено `inShort: false`. У Т3 короткой версии в программе нет.
- **Диапазоны веса в Т1/Т2** (14–16 кг, 27–32 кг, +5–10 кг) сохранены как `weightKg`…`weightKgMax`; приложение не выбирает вес за человека.
- **Dexie v3**: индексы `sessions.date`, `exerciseNotes.exerciseId`, `exerciseAliases.exerciseId`. `deletedAt` не индексируется (null не может быть ключом), удалённые отсеиваются в коде (`listRecords`).
- **Не сделано**: подпись RepDB на экране упражнения и в «О приложении» (экранов ещё нет), проверка ссылок `exerciseId` в записях на сервере (сервер не знает каталога).

## Этап 0.5. Аккаунт и синхронизация

- **Курсор — серверный счётчик `seq` на пользователя**, а не `updatedAt` клиента: часы устройств расходятся, и по ним изменения терялись бы. Счётчик увеличивается в той же транзакции, что и запись (строка `users` блокируется), поэтому параллельные push одного аккаунта не создают «дыр» в порядке выдачи.
- **Одна таблица `records(user_id, collection, id, data jsonb, …)`** вместо таблицы на сущность: сервер ничего не считает, статистику строит клиент, а схемы данных меняются быстрее, чем миграции. `data` пока проверяется только как объект; проверку по Zod-схемам коллекций подключит этап 1.
- **LWW на уровне записи**: сервер применяет запись, только если её `updatedAt` строго новее (одним оператором `INSERT … ON CONFLICT DO UPDATE … WHERE`). Равное время считается повторной отправкой и не меняет `seq`. Клиент делает `updatedAt = max(now, prev + 1)`, поэтому две быстрые правки не сравняются.
- **Очередь `outbox` хранит только ключ `collection:id`**, а содержимое берётся из таблицы в момент отправки: повторные правки схлопываются сами. Строка уходит из очереди, только если запись не менялась за время запроса; иначе дошлётся в том же проходе.
- **Pull после push**; применение серверных записей тоже по LWW: локальная версия не младше — остаётся и ждёт отправки. Курсор сохраняется после каждой страницы, обрыв посередине его не откатывает.
- **Триггеры синхронизации** (на iOS нет Background Sync): старт, `online`, возврат в приложение, раз в 60 с при видимой вкладке, через 2 с после записи. Контроллер одноколейный: параллельные запросы сводятся к одному повторному проходу.
- **Сессия**: случайный токен 32 байта, в базе только его SHA-256; cookie `sid` (`HttpOnly`, `SameSite=Lax`, 90 дней, продлевается при использовании не чаще раза в сутки). `Secure` включается в production (на http://localhost браузеры его не принимают).
- **Код входа**: 6 цифр, в базе HMAC-SHA256 с `AUTH_SECRET`; 10 минут, одноразовый, до 5 попыток (счётчик увеличивается атомарно до сравнения), новый код отменяет прежние, не более 5 кодов на почту за 10 минут, плюс лимит 20 запросов в минуту на IP. Любая причина отказа при проверке даёт одинаковый 401. Пользователь создаётся при первом успешном входе, поэтому запрос кода не раскрывает, есть ли почта в базе.
- **`userId` берётся только из сессии**; поля `userId` в теле запроса схема отбрасывает (покрыто тестом).
- **401 во время синхронизации** не стирает данные: приложение показывает экран входа, очередь остаётся и уходит после повторного входа. Если входит *другой* пользователь, локальные данные удаляются (чтобы не смешать аккаунты). При выходе данные удаляются всегда; если в очереди что-то есть, приложение предупреждает.
- **Без сети приложение открывается**: при ошибке сети `/me` используется сохранённый пользователь. Вход нужен один раз, и для него интернет обязателен.
- **БД**: Drizzle + PGlite локально и в тестах, `pg` в проде; миграции одни. PGlite можно повредить жёстким убийством процесса во время первой инициализации — для dev это приемлемо (удалить `server/.data`); боевая база — PostgreSQL. Дальше (проверено) обычная остановка процесса данные не теряет.
- **Dexie v2**: таблица на каждую коллекцию (`id, updatedAt`) и `outbox`; полноценные индексы появятся с этапом 1.
- **Сквозные тесты** лежат в `tests/e2e/`: клиентская синхронизация работает с настоящим сервером через `fastify.inject` и fake-indexeddb («два устройства», конфликты, обрыв сети, истёкшая сессия, изоляция пользователей).
- **Не сделано в этом этапе (намеренно)**: Apple и Яндекс ID, проверка `data` по схемам, экран «Профиль» с импортом/экспортом, отправка настоящей почты (нужен SMTP — этап 6).

## Этап 0. Каркас

- **npm workspaces** (`shared`, `design`, `client`, `server`). pnpm на машине нет, npm 11 достаточно.
- **Импорты с расширением `.ts`** и `allowImportingTsExtensions` в `tsconfig.base.json`: сборщики (Vite, tsx, Vitest) разрешают их без эмита, а `tsc` только проверяет типы (`noEmit`).
- **Zod-схемы живут в `shared/`**, а не в `client/src/domain/`, как сказано в промпте: их используют и клиент, и сервер. `domain/` будет содержать только чистые функции.
- **Токены**: `design/tokens.json` скопирован из артефакта дизайн-системы; `design/tokens-css.ts` генерирует `dist/tokens.css`. Алиасы (`strength = {cobalt}`) раскрываются при генерации. Тёмная тема включается по `prefers-color-scheme` и по `[data-theme="dark"]`; `[data-theme="light"]` принудительно возвращает светлую.
- **Шрифты локальные** (`@fontsource`, кириллица и латиница): работают офлайн и не зависят от Google. Из `bundle.css` убран `@import` Google Fonts.
- **Классы `htr-*`** скопированы из `bundle.css` в `client/src/styles/htr.css` без изменений (кроме удалённых `@import` и правила `body`).
- **PWA**: `vite-plugin-pwa` в режиме `generateSW`, `registerType: autoUpdate`, `navigateFallback` на `/index.html` с исключением `/api/`. Иконки генерирует `@vite-pwa/assets-generator` из одного SVG (слиток на `night`); maskable и apple-touch-icon с фоном `night`.
- **Один origin**: Vite проксирует `/api` на `localhost:8787` и в dev, и в preview — cookie сессии будут работать без CORS. `allowedHosts: true` в preview нужен, чтобы открывать его через туннель.
- **`navigator.storage.persist()`** вызывается один раз; факт запроса и ответ хранятся в таблице `meta`.
- **Роутер**: `react-router` v8 в режиме библиотеки (`BrowserRouter`). Тренировка — отдельный маршрут `/workout/:id` вне вкладок (полноэкранная поверх).
- **Версии** пакетов взяты актуальные на 27.10.2026 (React 19.3, Vite 8, Vitest 5, TypeScript 7, Zod 4); всё собралось без правок кода под них.
